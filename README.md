# evoref (Free Edition)

evoref は **完全ローカル動作** の自己進化型 LLM アシスタントです。外部 API・クラウドに一切依存せず、llama.cpp (llama-server) 上で GGUF モデルを動かし、RAG・記憶・自律実行ループ・自己学習を統合します。

会話を重ねるほど、記憶と経験の蓄積、プロンプトの進化を通じてあなたの環境に適応していきます。

---

## 主な機能

> 会話・記憶・学習データはすべて手元 (`local/`) に保存され、外部に送信されません。

### 完全ローカル / プライバシー

- 推論エンジンは llama.cpp (llama-server) 上で GGUF モデルをローカル実行。**インターネット接続なしで動作**します (外部 API への接続機能はありません)。
- 会話履歴・記憶・資料パック・学習データはすべて手元 (`local/`) に保存され、外部に送信されません。
- GPU が無くても **CPU only で動作可能** (`llama.gpu_layers: 0`)。Windows 11 / macOS / Linux 対応。

### チャット（RAG 付き会話・ファイル添付）

- 登録した資料 (資料パック) と過去の記憶を自動で検索し、**根拠を踏まえた回答**を生成します。
- 応答はストリーミングでリアルタイム表示 (Web UI / CLI 共通)。
- ファイルを添付して内容について質問でき、応答内のコードブロックは読みやすく表示されます。
- 日付・営業日・金額などの計算はモデルの暗算に任せず、**計算ツールと日付演算で接地**します (「来週の火曜日」のような相対日付も発話時点の絶対日付に解決)。
- 直前の自分の出力の文字数や、会話の中の発言回数といった問いには、システムが実測した値を渡します。

### ドキュメント検索（ハイブリッド RAG）

- キーワード一致 (転置索引) と意味の近さ (ベクトル検索) の両方から候補を集め、**取りこぼしの少ない検索**を行います。
- 日本語も MeCab などの追加インストール不要で扱えます (文字 bi-gram)。
- 質問に検索が必要かを自動判定 (Self-RAG) し、関係の薄い資料は使わず的外れな引用を抑えます。
- LangChain / Chroma / FAISS / sentence-transformers を使わない独自実装 (numpy + JSON + llama.cpp) で、すべて PC 内で完結します。

### 資料パック（`.evocart`）管理

- 資料をまとめた ZIP / `.evocart` を取り込むと資料パックとして登録され、自動で本文抽出・チャンク分割・索引化されます。
- 一覧 / ロード / アンロード / 削除 / 再構築を Web UI・CLI・API から操作できます。
- 複数の資料パックを横断して検索でき、会話の記憶と同じ仕組み (Evidence Store) で一本の順位付けに載ります。

### 記憶（Evidence Store）

- 会話はターンごとにノート化され (作業記憶 → 短期 → 長期)、長い会話でも文脈を見失いません。
- 名前・住まい・職業・家族・予定・好みなどを**属性ごとに構造化して長期記憶**し、別の会話でも想起できます。「予定が 1 週間延期になった」「本社ではなく名古屋支社」のような更新は、旧い値を置き換えて記録します。
- 「覚えておいて」などの発言は自動でピン留め (手動ピンも可)。ピン留めした記憶は自動削除されません。
- 「違います、正しくは…」という訂正は、本当に過去の誤りを指しているかを検証してから記憶に反映します (比較や引用を訂正と取り違えません)。アシスタントがその場で退けた主張は記憶に採用しません。
- 記憶の抽出・整理・統合は待機時間 (アイドル時) に裏で行われ、**応答の速さを犠牲にしません**。

### 自己学習（プロンプト進化）

- 「やり直して」「違う」などの訂正や、応答が役立ったかのサインを自動で読み取り、経験として記録します (評価ボタン不要)。
- うまくいった応答パターンを手本として蓄積し、似た質問が来たときに参考にします (その会話だけで成立する日付や金額、ユーザー固有の値は手本にしません)。
- アイドル時間にプロンプトを自動で進化させ、過去バージョンは履歴として保存 (ロールバック可)。
- 進化結果は実測の評価で比較し、**改善が確認できた場合だけ採用**します (悪化時は採用しない安全装置)。
- 学習はすべて手元で完結。`evoref serve --no-learning` で完全に OFF にもできます (チャット・RAG・記憶は通常どおり動作)。

### 自律エージェント・実行ループ

- 質問内容に応じて「即答」「ツールを使った調査つき回答」「タスクを分解する深掘り回答」を**自動で使い分け**ます。
- 必要なら URL 取得・コード検索・セッション内ファイルの読み書きを自動実行 (内部ネットワーク拒否・サイズ/タイムアウト上限・危険コマンドのブロックなど安全制約付き)。
- 目標を与えると、タスクを小さな段階に分解して順次実行し、生成物 (ファイル・コード・レポート等) を積み上げます。
- 各ステップで品質チェックを行い、失敗は類型化して後の改善に活用 (無限ループ防止の上限あり)。
- Web UI のライブコンソールで進捗をリアルタイムに観察でき、いつでも中断できます。

### 長文生成（記事・仕様書・レポート・創作）

- 「3000字の記事を書いて」「仕様書を作って」のような長文依頼を、構成を計画して段落単位で書き上げます。
- 技術文書・報告書向きの構成計画型と、物語・解説・創作向きの逐次生成型の 2 方式を内蔵し、依頼内容から自動選択します。
- 段落単位で文字数・文末の自然さ・重複を品質チェックし、短すぎる場合は再生成します。
- 「○○に保存して」「機能ごとに別ファイルで」と指示すると、単一ファイルや索引付きの複数ファイルに書き出せます (既存ファイルの上書きは自動回避)。ディレクトリ指定の無い書き出しは `local/outputs/` にまとまります。

### 操作（Web UI / CLI）

- **Web UI**: チャット / 会話履歴 / 資料パック管理 / メモリ閲覧 / 設定 / テーマの各画面。学習ダッシュボード (手本の一覧を含む)・RAG 統計・VRAM 使用量・ループ進捗のライブコンソールで状態を可視化します。
- **CLI**: `evoref chat` でリッチなストリーミング対話。`/save` `/load` (セッション)・`/cartridge` (資料パック)・`/theme`・`/file` (添付)・`/export` (書出)・`/loop`・`/history`・`/pin` `/unpin` `/pinned`・`/private`・`/learn`・`/status`・`/tasks`・`/web`・`/page`・`/reindex` などのスラッシュコマンドを利用でき、進行中の応答は Ctrl+C で中断できます。
- 日本語 / 英語の言語切替とテーマ切替に対応 (Web UI と CLI で共通)。

### 会話履歴・ファイル・データ移行

- 会話はターンごとに自動保存され、定期チェックポイントで異常終了時も失われません。古い会話は自動で要約圧縮され、キーワード・期間で検索・復元できます。
- ファイル読込: `txt` / `md` / `json` / `yaml` / コード / `html` / `pdf` / `csv` / `tsv` / `docx` / `xlsx` / `pptx` / `odt` / `ods` / `odp` / `rtf` / `eml` / `tex`。書出: `txt` / `md` / `html` / `csv` / `json` / `yaml` / `tex` / `docx` / `xlsx` / `pptx` / `odt` / `pdf` など。
- 記憶・経験・RAG・プロンプトを一括エクスポート / インポートでき、別環境への移行やバックアップに使えます (埋め込みモデルが異なる場合は互換性の警告を表示)。

### 応答と裏方処理の分離

- 1 つのベースモデルの中で、チャット応答用のスロットと、記憶の抽出・要約・ツール判定・学習などの裏方処理用のスロットを**分離**して動かします (`llama.slots`、既定 3)。裏方処理はチャットが来ると譲り、応答を待たせません。
- 起動時に必要 VRAM を自動見積もりし、予算を超えそうな場合は安全に起動を止めます (8K / 16K / 32K の長文対応レシピも用意)。
- 学習データはベースモデルごとに分けて保存されるので、モデルを差し替えても前のモデルの癖が混ざりません。

## 動作条件

| 項目 | 要件 |
|------|------|
| OS | Windows 11 / macOS / Linux |
| Python | 3.12 以上 |
| Node.js | npm 同梱の LTS |
| Git | 最新版 |
| llama-server | [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases) の build **b8946 以上**を推奨 (CVE-2026-21869 修正以降) |
| GPU / VRAM | GPU 推奨だが **CPU only でも動作** (`llama.gpu_layers: 0`)。必要 VRAM はモデルサイズ・`context_size`・並列スロット数 (`llama.slots`) に依存 (既定 base = gemma-4-12b-it-qat-q4_0 で概ね 8GB 前後)。埋め込みは既定で CPU 配置 |
| ディスク | GGUF モデル計 十数 GB (既定構成: base gemma-4-12b-it-qat-q4_0 / embed Qwen3-Embedding-0.6B)。`local/` データは運用に応じ別途数百 MB〜数 GB |

llama-server は setup では導入されません。**別途インストールして PATH を通す**必要があります。

## インストール

### 初回セットアップ

```powershell
# Windows / PowerShell
.\scripts\setup.bat
```

```bash
# macOS / Linux
./scripts/setup.sh
```

setup は以下を一括実行します:

1. Python 仮想環境 (`.venv`) 作成
2. Python 依存インストール (`backend/requirements.txt` + `pip install -e .`)
3. フロントエンド依存 (`npm install`)
4. `config.yaml.example` → `config.yaml` コピー
5. モデル配置チェック: `models/` に GGUF が配置されているか確認 (自動ダウンロードは行いません)
6. `local/` データディレクトリ生成

> **モデルは手動配置**: GGUF を `models/` に置き、`config.yaml` の `model_paths` と整合させてください。既定は base (gemma-4-12b-it-qat-q4_0) / embed (Qwen3-Embedding-0.6B)。配置状況は `python scripts/download_model.py` で確認できます。

#### オプション

```powershell
.\scripts\setup.bat --shared-path <NAS_PATH>   # 複数 PC で models/ を共有 (モデル配置チェックをスキップ)
.\scripts\setup.bat --force                    # .venv / config.yaml を強制再構築
```

複数 PC で使う場合、大きな GGUF モデルは NAS 上に共有しつつ、個人データ (履歴・記憶・学習) は各 PC の `local/` に独立して保持できます。

## 起動

```powershell
# 1. config.yaml を編集 (gpu_layers / context_size / slots をハードウェアに合わせる)
# 2. 一括起動 (llama-server 群 + FastAPI + SvelteKit)
.\scripts\evoref-ctl.bat start
.\scripts\evoref-ctl.bat start --no-learning   # 自己学習を止めて使う
.\scripts\evoref-ctl.bat status
.\scripts\evoref-ctl.bat stop
```

CLI (venv 有効化後):

```powershell
evoref serve   # backend + llama.cpp サーバ群
evoref chat    # 対話モード
evoref gui     # 既定ブラウザで Web UI を開く
```

`serve` / `chat` / `gui` には `--no-learning` (自己学習 OFF) と `--develop=<debug|investigate>` (詳細ログ) のオプションがあります。

### ポート

| サービス | ポート |
|----------|--------|
| Web UI | 5173 |
| backend (API) | 8000 |
| llama-server (base / embed) | 8080 / 8082 |

### データを初期化する

会話・記憶・学習データをすべて消して初期状態に戻すには、サービスを停止したうえで `python scripts/reset_local_data.py --no-restart` を実行します (`models/` のモデルと `config.yaml` は消えません)。

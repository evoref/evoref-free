# evoref (Free Edition)

evoref は **完全ローカル動作** の自己進化型 LLM アシスタントです。外部 API・クラウドに一切依存せず、llama.cpp (llama-server) 上で GGUF モデルを動かし、RAG・メモリ・自律実行ループ・自己学習を統合します。

会話を重ねるほど、経験記録とプロンプト進化を通じてあなたの環境に適応していきます。

---

## 主な機能

> 会話・記憶・学習データはすべて手元 (`local/`) に保存され、外部に送信されません。

### 完全ローカル / プライバシー

- 推論エンジンは llama.cpp (llama-server) 上で GGUF モデルをローカル実行。**インターネット接続なしで動作**します。
- 会話履歴・記憶・カートリッジ・学習データはすべて手元 (`local/`) に保存され、外部に送信されません。
- GPU が無くても **CPU only で動作可能** (`llama.gpu_layers: 0`)。Windows 11 / macOS / Linux 対応。

### チャット（RAG 付き会話・ファイル添付）

- 登録した資料 (カートリッジ) を自動で検索し、**根拠を踏まえた回答**を生成します。
- 応答はストリーミングでリアルタイム表示 (Web UI / CLI 共通)。
- ファイルを添付して内容について質問でき、応答内のコードブロックは読みやすく表示されます。

### ドキュメント検索（ハイブリッド RAG）

- キーワード一致 (BM25) と意味の近さ (ベクトル検索) を融合 (RRF) し、**取りこぼしの少ない検索**を行います。
- 日本語も MeCab などの追加インストール不要で扱えます。
- 質問に検索が必要かをモデルが自動判定 (Self-RAG) し、関係の薄い資料は使わず的外れな引用を抑えます。
- 無関係なカートリッジを自動で除外するゲート機能で、雑談やファイル生成依頼に資料の断片が紛れ込むのを防ぎます。
- LangChain / Chroma / FAISS / sentence-transformers を使わない独自実装 (numpy + JSON + llama.cpp) で、すべて PC 内で完結します。

### 資料パック（カートリッジ）管理

- 資料をまとめた ZIP を取り込むと「カートリッジ」として登録され、自動で本文抽出・チャンク分割・索引化されます。
- 一覧 / ロード / アンロード / 削除 / 再構築を Web UI・CLI・API から操作できます。
- 複数のカートリッジを横断して検索でき、現在のプロジェクトの記憶も検索に組み込めます。

### 記憶（短期・長期・意味記憶）

- 直前のやり取りを踏まえて応答し、長い会話でも文脈を見失いません (古い会話は自動で要約圧縮)。
- 名前・好み・コーディングスタイル・決定事項などを構造化して**長期記憶**し、プロジェクト単位と全体共有で範囲を分けられます。
- 「重要」「覚えておいて」などの発言を自動でピン留め (手動ピンも可)。ピン留めした記憶は自動削除されません。
- 使われない古い記憶は時間とともに整理され、よく参照する重要な記憶は残ります (記憶が無秩序に膨らまない)。
- 記憶の抽出・整理・統合は待機時間 (アイドル時) に裏で行われ、**応答の速さを犠牲にしません**。

### 自己学習（プロンプト進化）

- 「やり直して」「違う」などの訂正や、応答が役立ったかのサインを自動で読み取り、経験として記録します (評価ボタン不要)。
- うまくいった応答パターンを蓄積し、似た質問が来たときに自動で参考にします。
- アイドル時間にプロンプトや生成パラメータを自動で進化させ、過去バージョンは履歴として保存 (ロールバック可)。
- 進化結果は評価セットでスコアを比較し、**改善が確認できた場合だけ採用** (悪化時は自動で戻す安全装置)。
- 学習はすべて手元で完結。`evoref serve --no-learning` で完全に OFF にもできます (チャット・RAG・記憶参照は通常どおり動作)。

### 自律エージェント・実行ループ

- 質問内容に応じて「即答」「ツールを使った調査つき回答」「タスクを分解する深掘り回答」を**自動で使い分け**ます。
- 必要なら URL 取得・コード検索・セッション内ファイルの読み書きを自動実行 (内部ネットワーク拒否・サイズ/タイムアウト上限・危険コマンドのブロックなど安全制約付き)。
- 目標を与えると、タスクを小さな段階に分解して順次実行し、生成物 (ファイル・コード・レポート等) を積み上げます。
- 各ステップで品質チェックを行い、失敗は類型化して後の改善に活用 (無限ループ防止の上限あり)。
- Web UI のライブコンソールで進捗をリアルタイムに観察でき、いつでも中断できます。

### 長文生成（記事・仕様書・レポート・創作）

- 「3000字の記事を書いて」「仕様書を作って」のような長文依頼を、構成を計画して段落単位で書き上げます。
- 技術文書・報告書向きの構成計画型と、物語・解説・創作向きの逐次生成型の 2 方式を内蔵し、依頼内容から自動選択します。
- 段落単位で文字数・文末の自然さ・重複を品質チェックし、短すぎる場合は再生成します。
- 「○○に保存して」「機能ごとに別ファイルで」と指示すると、単一ファイルや索引付きの複数ファイルに書き出せます (既存ファイルの上書きは自動回避)。

### 操作（Web UI / CLI）

- **Web UI**: チャット / 会話履歴 / カートリッジ管理 / メモリ閲覧 / 設定 / テーマの各画面。学習ダッシュボード・RAG 統計・VRAM 使用量のモデル別表示・ループ進捗のライブコンソールで状態を可視化します。
- **CLI**: `evoref chat` でリッチなストリーミング対話。`/save` `/load` (セッション)・`/cartridge` (資料管理)・`/theme`・`/file` (添付)・`/export` (書出)・`/loop`・`/memory`・`/history` などのスラッシュコマンドを利用でき、進行中の応答は Ctrl+C で中断できます。
- 日本語 / 英語の言語切替とテーマ切替に対応 (Web UI と CLI で共通)。

### 会話履歴・ファイル・データ移行

- 会話はターンごとに自動保存され、定期チェックポイントで異常終了時も失われません。古い会話は自動で要約圧縮され (既定: 原文 90 日 / 圧縮 365 日 / 上限 200MB)、キーワード・期間で検索・復元できます。
- ファイル読込: `txt` / `md` / `json` / `yaml` / コード / `html` / `pdf` / `csv` / `tsv`。書出: `txt` / `md` / `html` / `csv` / `tsv` / `json` / `yaml` / `tex`。
- 記憶・経験・RAG・プロンプト・カートリッジの 5 カテゴリを一括エクスポート/インポートでき、別環境への移行やバックアップに使えます (埋め込みモデルが異なる場合は互換性の警告を表示)。

### 高速応答の仕組み（base / assist モデル分離）

- チャット応答用の大型モデル (base) と、記憶抽出・検索判定・要約などの裏方処理用の小型モデル (assist) を**別プロセスで動かし**、応答速度と品質を両立します。
- 裏方の assist が起動失敗・故障してもチャットは縮退モードで継続し、状態は Web UI のバナーで確認できます。
- 起動時に必要 VRAM を自動見積もりし、予算を超えそうな場合は安全に起動を止めます (8K / 16K / 32K の長文対応レシピも用意)。

## 動作条件

| 項目 | 要件 |
|------|------|
| OS | Windows 11 / macOS / Linux |
| Python | 3.12 以上 |
| Node.js | npm 同梱の LTS |
| Git | 最新版 |
| llama-server | [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases) の build **b8946 以上**を推奨 |
| GPU / VRAM | GPU 推奨だが **CPU only でも動作** (`llama.gpu_layers: 0`)。Qwen3.5-9B Q4_K_M + KV キャッシュで VRAM **3〜5GB** が目安。埋め込み・リランカーは既定で CPU 配置 |
| ディスク | GGUF モデル計 **約 9GB** (base ~5.5GB / assist ~2.4GB / embedding ~0.6GB / reranker ~0.3GB)。`local/` データは運用に応じ別途数百 MB〜数 GB |

llama-server は setup では導入されません。**別途インストールして PATH を通す**必要があります。

## インストール

### 初回セットアップ

```powershell
# Windows / PowerShell
.\scripts\setup.bat
```

```bash
# macOS / Linux
./scripts/setup.sh
```

setup は以下を一括実行します:

1. Python 仮想環境 (`.venv`) 作成
2. Python 依存インストール (`backend/requirements.txt` + `pip install -e .`)
3. フロントエンド依存 (`npm install`)
4. `config.yaml.example` → `config.yaml` コピー
5. モデルダウンロード (対話式 Y/n): base (Qwen3.5-9B) / assist (Qwen3.5-4B) / embedding (Qwen3-Embedding-0.6B) / reranker (Qwen3-Reranker-0.6B)
6. `local/` データディレクトリ生成

#### オプション

```powershell
.\scripts\setup.bat --shared-path <NAS_PATH>   # 複数 PC で models/ を共有 (DL スキップ)
.\scripts\setup.bat --force                    # .venv / config.yaml / models を強制再構築
```

複数 PC で使う場合、大きな GGUF モデルは NAS 上に共有しつつ、個人データ (履歴・記憶・学習) は各 PC の `local/` に独立して保持できます。

## 起動

```powershell
# 1. config.yaml を編集 (gpu_layers / context_size をハードウェアに合わせる)
# 2. 一括起動 (llama-server 群 + FastAPI + SvelteKit)
.\scripts\evoref-ctl.bat start
.\scripts\evoref-ctl.bat status
.\scripts\evoref-ctl.bat stop
```

CLI (venv 有効化後):

```powershell
evoref serve   # backend + llama.cpp サーバ群
evoref chat    # 対話モード
evoref gui     # 既定ブラウザで Web UI を開く
```

### ポート

| サービス | ポート |
|----------|--------|
| Web UI | 5173 |
| backend (API) | 8000 |
| llama-server (base / assist / embed) | 8080 / 8081 / 8082 |
| llama-server (rerank, 任意) | 8083 |

リランカー (8083) は既定で無効 (`reranker.enabled: false`)。RAG はリランカー無しでも動作し、検索精度を上げたい場合に有効化します。
